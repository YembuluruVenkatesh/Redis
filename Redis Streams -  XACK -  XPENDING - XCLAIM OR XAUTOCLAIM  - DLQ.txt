XPENDING (Pending Entries List): 

Why is XPENDING useful?

Suppose your application processes payments.

Receive Payment Event
        │
        ▼
Debit Customer
        │
        ▼
💥 Server Crash

Without Redis Streams:

❌ Payment event is lost.

With Redis Streams:

Pending Entries List

Payment Event
Status = Pending

When the service restarts, it can continue processing.

One important note: 


The retry implementation above is great for learning, but it's not how production systems recover messages.

In production, Redis provides:

XPENDING → inspect pending messages
XCLAIM → transfer ownership of a pending message to another consumer
XAUTOCLAIM → automatically claim idle pending messages

Those commands solve cases like:

Consumer-1

↓

Receives Message

↓

Crashes

↓

Consumer-2

↓

Claims Message

↓

Processes

↓

ACK

This is the production-grade approach.
